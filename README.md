# نظام ERP — وكالة هاشم عبده فارع البراق (qaatSystem)

نظام محاسبي/مخزني متكامل مبني على **Laravel 12 / PHP 8.2+ / MySQL / Bootstrap RTL**، يغطي دورة
الأعمال الكاملة من الشراء والتوزيع إلى البيع والمرتجعات والسندات والقيود المحاسبية والتقارير والنسخ الاحتياطي.

> هذه النسخة هي النسخة النهائية بعد تطبيق خطة الإصلاح الأمني والفني الكاملة
> (الفحص الشامل F-01 → F-20 + إصلاحات إضافية اكتشفها الاختبار الآلي).
> راجع ملف **تقرير الإصلاحات الشامل** المرفق مع الحزمة لتفاصيل كل تعديل بالأدلة.

## 2) المتطلبات

- PHP **8.2** أو أحدث (الامتدادات: `pdo_mysql mbstring openssl tokenizer xml ctype json bcmath`)
- MySQL **5.7+** أو MariaDB **10.3+**
- Composer 2
- Node.js 18+ و npm (لإعادة بناء الواجهة — مجلد `public/build` جاهز داخل الحزمة أصلاً)

## 3) التثبيت من الصفر (خطوة بخطوة)

```bash
# 1) تبعيات PHP
composer install --optimize-autoloader --no-dev

# 2) ملف البيئة
cp .env.example .env
#   ثم عدّل قيم قاعدة البيانات (DB_DATABASE / DB_USERNAME / DB_PASSWORD)
#   وAPP_URL وADMIN_PASSWORD

# 3) مفتاح التشفير (إلزامي — لا تستخدم مفتاحاً من بيئة أخرى)
php artisan key:generate

# 4) الهجرات + حساب مدير النظام + دليل الحسابات
php artisan migrate --seed

# 5) التخزين المؤقت للإنتاج
php artisan config:cache
php artisan route:cache
php artisan view:cache

# 6) (اختياري) إعادة بناء أصول الواجهة إن احتجت تعديلها
npm ci && npm run build
```

**بيانات الدخول الافتراضية** (أو ما ضبطته في `ADMIN_EMAIL`/`ADMIN_PASSWORD` قبل البذر):

| الحساب | البريد | كلمة المرور |
|---|---|---|
| مدير النظام | `admin@erp.local` | `Admin@12345` |

> ⚠️ **إلزامي**: سجّل الدخول فوراً وغيّر كلمة المرور من قائمة المستخدم (أعلى اليسار) ← "تغيير كلمة المرور".

## 4) المستخدمون والأدوار (جديد)

| الدور | الصلاحيات |
|---|---|
| **مدير النظام** (admin) | كل شيء + إدارة المستخدمين + النسخ الاحتياطي + تصدير البيانات |
| **محاسب** (accountant) | كل العمليات التشغيلية (فواتير، سندات، قيود، تقارير) دون الإدارة والنسخ الاحتياطي |
| **مشاهد** (viewer) | عرض وطباعة فقط |

- إنشاء المستخدمين وإدارة الأدوار: **الإعدادات ← المستخدمون** (للمدير فقط).
- تعطيل الحساب يمنع الدخول فوراً ويُنهي جلسة المعطل.
- كلمة المرور المفقودة تُعاد تعيينها من شاشة المستخدمين (كلمة عشوائية آمنة تُعرض مرة واحدة).

## 5) الطوابير والجدولة على الاستضافة (مهم)

عمليات **التصدير/الاستيراد الاحتياطي** تعمل على طابور `backups`:

### الخيار أ — استضافة تدعم Cron فقط (شائعة)
اترك `QUEUE_CONNECTION=database` وأضف مهمة cron كل دقيقة:

```cron
* * * * * cd /path/to/project && php artisan schedule:run >> /dev/null 2>&1
* * * * * cd /path/to/project && php artisan queue:work --queue=backups --stop-when-empty --tries=1 >> /dev/null 2>&1
```

### الخيار ب — تنفيذ فوري بلا عامل (أسهل على الاستضائف المشتركة)
اضبط في `.env`:

```env
QUEUE_CONNECTION=sync
```

ستُنفَّذ عمليات النسخ الاحتياطي مباشرة مع الطلب (أبطأ لكن بلا متطلبات).

### الخيار ج — خادم مخصص (Supervisor)
```ini
[program:erp-queue]
command=php /path/to/project/artisan queue:work --queue=backups --sleep=3 --tries=3
numprocs=1
autostart=true
autorestart=true
```

الجدولة (تنظيف النسخ الاحتياطي 02:00 وتقليم الطوابير) تعمل عبر `schedule:run` بمهمة cron كل دقيقة (الخيار أ يشملها).

## 6) النشر عبر FTP (سكربتات scripts/)

سكربتات النشر موجودة للتوافق مع طريقة العمل الحالية، لكن **بيانات الاعتماد لم تعد مكتوبة داخلها**
(كانت مكشوفة نصاً — إصلاح F-03):

1. انسخ `scripts/ftp.credentials.example.ps1` إلى `scripts/ftp.credentials.ps1`
2. ضع بيانات استضافتك الحقيقية فيه
3. شغّل النشر كالعادة:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\deploy-smart-v3.ps1
# معاينة فقط: أضف -DryRun
```

ملف `ftp.credentials.ps1` مستثنى من Git ومن حزمة التسليم — لا يُرفع أبداً.

## 7) النسخ الاحتياطي

- الشاشة: **الإعدادات ← إعدادات النظام** (مدير النظام فقط — إصلاح F-02).
- التصدير ينتج ملف SQL كامل (باستثناء الجداول النظامية) مع ملف تحقق `sha256`.
- الاستيراد يستبدل كل البيانات — يوصى بالاحتفاظ بنسخة خارجية مشفرة.
- كلمة مرور قاعدة البيانات تُمرر لعميل MySQL عبر ملف مؤقت بصلاحيات 0600 (لا تظهر في قائمة العمليات — إصلاح F-15).

| الإصلاح | الوصف |

| **F-06** | منع الحذف المتسلسل للسندات: restrict + فحص استخدام قبل حذف أي حساب |

| **F-09** | تحديد المعدل على الدخول/التصدير/النسخ + إصلاح سباق كتابة الجلسة |

| **F-11** | تصحيح تسميات PSR-4 (كانت تنكسر على Linux) |
| **F-12** | أصول الواجهة المبنية مضمّنة (`public/build`) — الحزمة تعمل بلا npm |
| **F-15** | كلمة مرور MySQL خارج سطر الأوامر + أذونات مجلدات 0755 |
| **F-16** | إجبار HTTPS + تشفير الجلسة + كوكيز آمنة (Secure/HttpOnly/SameSite=strict) |
| **F-17** | ترقيم المستندات بعداد ذرّي لا يعيد استخدام الأرقام المحذوفة |

**إصلاحات إضافية اكتشفها الاختبار الآلي (137 اختباراً):**
- توافق الهجرات مع MySQL على Linux (حساسية أحرف أسماء الجداول + 9 أخطاء صياغة كانت تُسقط `migrate` نهائياً)
- إصلاح انهيار كل عملية ترحيل عند غياب العملة النظامية (قيمة افتراضية خاطئة `coinsID=1`)
- إصلاح الكاش الساكن للعملة عبر الطلبات في `AccountBalanceService`
- توحيد `total_in_base_currency` مع القيد المحاسبي (التكاليف الإضافية مشمولة)
- إصلاح 8 فئات Resources كانت تنكسر على خوادم Linux حساسة للأحرف

## 9) التحقق اليدوي بعد التثبيت (قائمة فحص)

```bash
# 1) الصحة والبنية
php artisan about                              # الحزمة سليمة
php artisan migrate:status                     # كل الهجرات مقفلة (Ran)
php artisan route:list                         # 239 مساراً تقريباً

# 2) الأمان
#   - افتح الموقع من متصفح آخر دون دخول → يجب التحويل إلى /login
#   - أرسل طلب API بدون جلسة → 401 JSON
#   - جرّب الدخول بكلمة مرور خاطئة 6 مرات → رسالة "محاولات كثيرة"

# 3) دورة أعمال سريعة
#   - أنشئ عملاء/مورد + عملة نظامية (coinsSystem=1) + مخزن + صنف
#   - فاتورة شراء → تُرحّل تلقائياً (قيد + حركة مخزون)
#   - فاتورة بيع → ترحيل تلقائي + COGS
#   - مرتجع بيع → قيد عكسي + حركة in

#   - ميزان المراجعة → المدين = الدائن

# 4) الاختبارات الآلية (يحتاج MySQL اختباري)
DB_DATABASE=qaat_system_test DB_USERNAME=root DB_PASSWORD=... vendor/bin/phpunit
#   النتيجة المتوقعة: OK (137 tests, 916 assertions)

# 5) النسخ الاحتياطي (مدير فقط)
#   الإعدادات ← إعدادات النظام ← تصدير → تنزيل الملف والتحقق منه
```

## 10) استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| صفحة بيضاء أو خطأ `manifest.json` | نفّذ `npm ci && npm run build` أو تأكد من وجود `public/build` |
| `Class "..." not found` بعد النشر | `composer dump-autoload -o` على الخادم |
| 500 عند أي ترحيل محاسبي | تأكد من وجود **عملة نظامية** (`coinsSystem=1`) والحسابات النظامية (Seeder) |
| عمليات النسخ الاحتياطي لا تكتمل | راجع قسم الطوابير (5) — الطابور بحاجة لعامل أو `QUEUE_CONNECTION=sync` |
| لا يمكن حذف حساب تحليلي | هذا سلوك مقصود (F-06) — الحساب مستخدم في مستندات؛ راجع الرسالة |
| `419 Page Expired` | حدّث الصفحة (توكن CSRF) — طبيعي بعد خمول الجلسة |
